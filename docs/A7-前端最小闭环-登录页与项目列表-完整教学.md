### 1.2 怎样延续你以前的代码风格

你现有代码的特点是：类型明确、职责分层、函数名能说明用途、参数较多时分行、关键步骤有中文注释。前端也按这个思路写：

- HTTP 请求集中在 `api/`，页面不散落 `fetch()`。
- 后端 DTO 与页面类型分开，统一在 API 模块转换字段。
- 复杂动作使用具名函数，按“校验 → 请求 → 更新状态”顺序展开。
- 使用 TypeScript 的 `type` 表达数据合同，避免 `any`。
- 组件使用 PascalCase，函数和普通变量使用 camelCase；HTTP JSON 继续使用 snake_case。

前端不使用 Pydantic 的 `Field()`。TypeScript 类型用于开发期检查，表单 `rules` 用于界面校验，后端 Pydantic 才是最终输入边界。不能把 Python 语法直接搬进 TSX。

## 2. 动手前先读懂整个链路

```text
浏览器页面 http://127.0.0.1:5173
  │ 相对路径 fetch('/api/v1/projects')
  ▼
Vite 开发代理
  │ 保留 /api/v1 路径，转发到 127.0.0.1:8000
  ▼
FastAPI
  │ 检查 Cookie → 检查权限 → 写操作检查 Origin 和 CSRF
  ▼
项目服务 → PostgreSQL → 返回统一 JSON
  ▼
API 模块把 snake_case 转成 camelCase
  ▼
TanStack Query 管理请求与缓存 → React 渲染界面
```

### 2.1 你需要认识的前端词汇

| 名称 | 放在这个项目里怎么理解 |
|---|---|
| React 组件 | 一个返回界面的函数，如 `LoginPage` |
| JSX / TSX | 在 JavaScript / TypeScript 文件中描述 HTML 风格界面的语法 |
| props | 父组件传给子组件的参数 |
| state | 输入内容、弹窗开关、当前游标等会变化的数据 |
| Hook | React 中以 `use` 开头的函数，只能在组件或自定义 Hook 顶层调用 |
| 路由 | 按 `/login`、`/projects` 选择页面 |
| Query | 读取服务端数据，如查询项目列表 |
| Mutation | 修改服务端数据，如创建、归档项目 |
| DTO | 网络传输的数据类型，字段与后端完全一致 |
| Promise / async / await | 表达“请求要等一会儿，拿到结果后再继续” |
| 泛型 `<T>` | 让同一个响应外壳可以包裹不同业务类型 |
| 乐观锁 | 提交读取时的版本号，后端发现过期就拒绝覆盖 |
| 幂等键 | 标记同一次写操作，响应丢失后可以用同一个键重试 |

React 渲染和向后端写数据是两件事。不能在组件函数执行时直接创建项目；写操作放在用户点击后触发的处理函数中。

### 2.1.1 第一次读 TypeScript/React 时，看懂这些语法就够了

例如下面这段只是讲语法，不需要新建文件：

```tsx
type ExampleProps = {
  name: string;
  busy?: boolean;
  onConfirm: () => void;
};

function Example({ name, busy = false, onConfirm }: ExampleProps) {
  return <button disabled={busy} onClick={onConfirm}>确认 {name}</button>;
}
```

- `name: string` 类似 Python 的 `name: str`，表示这是字符串。
- `busy?: boolean` 中的 `?` 表示属性可省略，`busy = false` 给省略时的默认值。
- `() => void` 表示“不接收参数，也不返回业务数据的函数”。
- `{ name, busy, onConfirm }` 是从 props 对象取出对应属性，叫解构。
- JSX 里的 `{name}` 表示把变量值放进界面；标签外的 TypeScript 仍是普通代码。
- `onClick={onConfirm}` 传递函数，等点击时执行；写成 `onClick={onConfirm()}` 会在渲染时就执行。

再看项目中常见的一句：

```ts
const [createOpen, setCreateOpen] = useState(false);
```

`createOpen` 是当前值，`setCreateOpen(true)` 请求 React 用新值重新渲染。不要直接写 `createOpen = true`。`const` 表示当前绑定不重新赋值，状态更新由 React 管理。

常见表达式也可以对照着读：

| 写法 | 含义 |
|---|---|
| `query.data?.items` | data 有值时才取 items，避免读空对象 |
| `query.data?.items ?? []` | 没有 items 时使用空数组；不把合法的 0/false 当成缺失 |
| `condition && <Component />` | 条件满足时才渲染该组件 |
| `condition ? a : b` | 条件成立取 a，否则取 b |
| `...values` | 浅复制对象字段，后续字段可覆盖前面同名字段 |
| `await request(...)` | 等异步请求完成再继续，不阻塞整个浏览器 UI |
| `try/catch/finally` | 分别处理正常结果、失败，以及两者都要做的清理 |
| `void query.refetch()` | 明确忽略返回的 Promise；请求状态仍交给 Query 管理 |
| `import type { Project }` | 只导入编译时类型，浏览器运行时没有这个对象 |

Hook 必须在组件顶层按固定顺序调用。可以在 Hook 调用之后根据状态提前 `return`，不能把 `useState` 或 `useQuery` 放进 `if` 里。

### 2.2 先把接口合同写清楚

以下路径都带 `/api/v1`：

| 方法、路径 | 请求 | 成功响应 `data` | 额外要求 |
|---|---|---|---|
| `POST /auth/login` | `organization_slug/email/password` | `user/organization/csrf_token` | Origin；无需 CSRF |
| `GET /auth/me` | 无 | 同登录响应 | Cookie；刷新时恢复状态 |
| `POST /auth/logout` | 无 | 无，HTTP 204 | Cookie、CSRF、Origin |
| `POST /auth/password` | `current_password/new_password` | `user/csrf_token` | Cookie、CSRF、Origin；轮换会话 |
| `GET /projects` | 查询参数 `limit/cursor/q/status` | `items/next_cursor/has_more` | admin/writer/reviewer |
| `POST /projects` | 项目基本信息 | 一个项目，HTTP 201 | admin/writer；幂等键可选 |
| `POST /projects/{id}/archive` | `expected_lock_version` | 一个项目 | 仅 admin；幂等键必需 |

成功外壳：

```json
{
  "data": { "items": [], "next_cursor": null, "has_more": false },
  "request_id": "由后端生成的请求编号"
}
```

失败外壳：

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "内容已更新，请比较最新版本后重新保存。",
    "details": { "current_lock_version": 4 },
    "retryable": false
  },
  "request_id": "由后端生成的请求编号"
}
```

不要把整个成功外壳当项目，也不要假设列表直接返回数组。当前 `user_summary()` 没返回 `created_at`，本文用户 DTO 不把它设成必需字段。

### 2.3 三个会影响验收的实际情况

1. `scripts/create_demo_data.py` 只创建 writer 和 reviewer，**不会创建 admin**。writer 可新建项目，但不能归档。
2. 演示脚本默认 `must_change_password=true`，业务接口会返回 `PASSWORD_CHANGE_REQUIRED`。本文提供一个小型首次改密页，保证正常安全流程能走通。
3. `ensure_no_active_runs()` 目前是 A8 待实现的占位函数。前端会处理 `RUNS_ACTIVE`，但“真实存在运行时拒绝归档”须等 A8 后端完成，A7 不能宣称已经验证。

## 4. 第二步：代理、Origin 与代码规范

### 4.1 配置 Vite

手动替换 `frontend/vite.config.ts`，完整内容：

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    host: '127.0.0.1',
    port: 5173,
    strictPort: true,
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8000',
        changeOrigin: false,
      },
    },
  },
  preview: {
    host: '127.0.0.1',
    port: 5173,
    strictPort: true,
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8000',
        changeOrigin: false,
      },
    },
  },
});
```

解释：

- 浏览器始终向 `5173` 发送请求，由 Vite 转发到 `8000`。
- 不写 `rewrite`：FastAPI 本来就需要完整 `/api/v1/...`。
- `strictPort` 防止 5173 被占用后自动换端口，导致 Origin 不匹配。
- 本机后端无虚拟主机需求，保留请求来源即可；不能依赖 `changeOrigin` 替你修复业务上的 Origin 校验。
- preview 也明确配置同端口代理，便于本地检查构建产物。dev 与 preview 不能同时占用 5173。

Vite 的代理仅用于本地开发/预览。生产环境需要 Nginx 等入口把 `/api/` 转发给后端，不能把 `vite preview` 当生产服务。配置依据：[server.proxy](https://vite.dev/config/server-options)、[preview.proxy](https://vite.dev/config/preview-options)。

### 4.2 用启动环境变量对齐后端 Origin

不需要为了这次练习修改 `.env`。新开 PowerShell 终端，在根目录执行：

```powershell
Set-Location D:\proj\harness
$env:ENV = 'dev'
$env:SECURITY__PUBLIC_ORIGIN = 'http://127.0.0.1:5173'
uv run uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

这两个变量只作用于当前终端启动的进程；其余数据库、Redis、CSRF 密钥仍来自你已有配置。不要在前端配置中复制后端密钥。

再开前端终端：

```powershell
Set-Location D:\proj\harness\frontend
npm run dev
```

统一使用 `http://127.0.0.1:5173`。`localhost` 与 `127.0.0.1` 是不同主机名，不要混用。后端实际读取的是嵌套变量 `SECURITY__PUBLIC_ORIGIN`，不是设计文档里的简写 `PUBLIC_ORIGIN`。

浏览器打开 `http://127.0.0.1:5173/api/v1/auth/me`，未登录时得到统一 JSON 的 `401 SESSION_EXPIRED`，说明代理能接通。这里的 401 是预期结果。

如果登录 POST 返回 `403 CSRF_INVALID`，先检查 Network 中请求的 Origin 与后端环境变量是否完全相同，再查 CSRF；登录本身不要求 CSRF Token。

## 5. 第三步：先写数据类型，再写请求

### 5.1 公共类型

新增 `frontend/src/api/types.ts`：

```ts
/** 普通成功响应，T 表示本次接口实际返回的数据。 */
export type SuccessResponse<T> = {
  data: T;
  request_id: string;
};

export type CursorPageDto<T> = {
  items: T[];
  next_cursor: string | null;
  has_more: boolean;
};

export type CursorPage<T> = {
  items: T[];
  nextCursor: string | null;
  hasMore: boolean;
};

export type UserRole = 'admin' | 'writer' | 'reviewer';

export type UserDto = {
  id: string;
```

```ts
export class ApiError extends Error {
  readonly status: number;
  readonly code: string;
  readonly requestId: string | null;
  readonly retryable: boolean;
  readonly details: Record<string, unknown>;
  readonly retryAfter: string | null;

  constructor(
    status: number,
    code: string,
    requestId: string | null = null,
    retryable = false,
    details: Record<string, unknown> = {},
    retryAfter: string | null = null,
  ) {
    const fallback = status === 429 ? '操作太频繁，请稍后重试。' : '请求未完成，请稍后重试。';
    super(ERROR_MESSAGES[code] ?? fallback);
    this.name = 'ApiError';
    this.status = status;
    this.code = code;
    this.requestId = requestId;
    this.retryable = retryable;
    this.details = details;
    this.retryAfter = retryAfter;
  }

export function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

/** 保留结构化字段，界面文案由前端维护，不直接显示服务器原文。 */
export function readApiError(response: Response, body: unknown): ApiError {
  let code = response.status >= 500 ? 'INTERNAL_ERROR' : 'HTTP_ERROR';
  let requestId = response.headers.get('X-Request-ID');
  let retryable = response.status >= 500;
  let details: Record<string, unknown> = {};

  if (isRecord(body)) {
    if (typeof body.request_id === 'string') requestId = body.request_id;
    if (isRecord(body.error)) {
      if (typeof body.error.code === 'string') code = body.error.code;
      if (typeof body.error.retryable === 'boolean') retryable = body.error.retryable;
      if (isRecord(body.error.details)) details = body.error.details;
    }
  }

  return new ApiError(
    response.status,
    code,
    requestId,
    retryable,
    details,
    response.headers.get('Retry-After'),
  );
}

export function errorMessage(error: unknown): string {
  if (error instanceof ApiError) return error.message;
  return '操作未完成，请稍后重试。';
}
```

### 5.4 统一接口客户端

新增 `frontend/src/api/client.ts`：

```ts
import { ApiError, isRecord, readApiError } from './errors';
import {
  getCsrfToken,
  getSessionGeneration,
  notifySessionExpired,
} from './session';
import type { SuccessResponse } from './types';

type RequestOptions = {
  method?: 'GET' | 'POST' | 'PATCH' | 'DELETE';
  body?: unknown;
  signal?: AbortSignal;
  idempotencyKey?: string;
  csrf?: boolean;
  redirectOnExpired?: boolean;
};

/** 同源 JSON 客户端：错误转换、CSRF、超时、取消与过期通知。 */
export async function request<T>(path: string, options: RequestOptions = {}): Promise<T> {
  const method = options.method ?? 'GET';
  const headers = new Headers({ Accept: 'application/json' });
  const generation = getSessionGeneration();
  const controller = new AbortController();
  let timedOut = false;

  function abortFromCaller(): void {
    controller.abort();
  }

  if (options.signal?.aborted) controller.abort();
  options.signal?.addEventListener('abort', abortFromCaller, { once: true });

  if (options.body !== undefined) headers.set('Content-Type', 'application/json');
  if (options.idempotencyKey) headers.set('Idempotency-Key', options.idempotencyKey);

  if (method !== 'GET' && options.csrf !== false) {
    const token = getCsrfToken();
    if (!token) {
      options.signal?.removeEventListener('abort', abortFromCaller);
      throw new ApiError(0, 'CSRF_MISSING');
    }
    headers.set('X-CSRF-Token', token);
  }

  const timeoutId = window.setTimeout(function abortOnTimeout() {
    timedOut = true;
    controller.abort();
  }, 15000);

  try {
    const response = await fetch(`/api/v1${path}`, {
      method,
      headers,
      credentials: 'same-origin',
      body: options.body === undefined ? undefined : JSON.stringify(options.body),
      signal: controller.signal,
    });

    let body: unknown = null;
    if (response.status !== 204) {
      const text = await response.text();
      try {
        body = text ? JSON.parse(text) : null;
      } catch {
        body = null;
      }
    }

    if (generation !== getSessionGeneration()) {
      throw new DOMException('旧会话请求已取消', 'AbortError');
    }

    if (!response.ok) {
      const error = readApiError(response, body);
      if (
        error.status === 401 &&
        error.code === 'SESSION_EXPIRED' &&
        options.redirectOnExpired !== false
      ) {
        notifySessionExpired();
      }
      throw error;
    }

    if (response.status === 204) return undefined as T;
    if (!isRecord(body) || !('data' in body) || typeof body.request_id !== 'string') {
      throw new ApiError(response.status, 'INVALID_RESPONSE');
    }

    return (body as SuccessResponse<T>).data;
  } catch (error: unknown) {
    if (generation !== getSessionGeneration()) {
      throw new DOMException('旧会话请求已取消', 'AbortError');
    }
    if (options.signal?.aborted) throw error;
    if (timedOut) throw new ApiError(0, 'REQUEST_TIMEOUT', null, true);
    if (error instanceof ApiError) throw error;
    if (error instanceof DOMException && error.name === 'AbortError') throw error;
    throw new ApiError(0, 'NETWORK_ERROR', null, true);
  } finally {
    window.clearTimeout(timeoutId);
    options.signal?.removeEventListener('abort', abortFromCaller);
  }
}
```

逐段理解：

1. 页面只传业务路径，如 `/projects`，客户端统一加 `/api/v1`。
2. Cookie 由浏览器自动携带，代码不读取、不拼接 `bid_session`。
3. 写操作默认加 `X-CSRF-Token`；只有登录调用明确设置 `csrf: false`。
4. 只对明确的 `SESSION_EXPIRED` 执行全局过期处理。密码错也是 401，不能把它误当会话过期。
5. 204 没有 JSON，不调用 JSON 解析。
6. 代理 502 可能返回 HTML，解析失败仍然变成人能理解的错误。
7. 15 秒只是前端等待上限，不代表数据库事务被撤销；写操作超时后需要复用幂等键或先查询结果。
8. `AbortSignal` 让 Query 可以取消离开页面后的读取；接口实际业务数据暂靠类型合同，外壳做运行时检查。完整运行时 DTO 校验可以以后引入 schema 库，不能声称 `as T` 验证了 JSON。

### 6.5 保留安全的站内返回地址

```ts
/** 当前 A7 只允许回到项目页，拒绝外部 URL 和登录页循环。 */
export function safeReturnTo(value: string | null): string {
  if (!value || !value.startsWith('/') || value.startsWith('//')) return '/projects';

  try {
    const url = new URL(value, window.location.origin);
    if (url.origin !== window.location.origin || url.pathname !== '/projects') {
      return '/projects';
    }
    return `${url.pathname}${url.search}${url.hash}`;
  } catch {
    return '/projects';
  }
}

export function loginUrl(returnTo: string, expired: boolean): string {
  const params = new URLSearchParams({ returnTo: safeReturnTo(returnTo) });
  if (expired) params.set('reason', 'session_expired');
  return `/login?${params}`;
}
```

返回地址放 URL 参数，刷新登录页不会丢；不放用户身份。以后增加项目详情路由时，再扩展允许的站内路径。不能直接信任任意 `returnTo`，否则登录后可能跳往外部地址。

### 6.6 全局处理会话过期

新增 `frontend/src/app/SessionEvents.tsx`：

```tsx
import { useEffect } from 'react';
import { useQueryClient } from '@tanstack/react-query';
import { useLocation, useNavigate } from 'react-router-dom';
import { clearSessionMemory, SESSION_EXPIRED_EVENT } from '../api/session';
import { loginUrl } from '../features/auth/redirect';

export function SessionEvents() {
  const queryClient = useQueryClient();
  const navigate = useNavigate();
  const location = useLocation();

  useEffect(() => {
    function handleExpired(): void {
      const returnTo = `${location.pathname}${location.search}${location.hash}`;
      clearSessionMemory();
      void queryClient.cancelQueries();
      queryClient.clear();
      navigate(loginUrl(returnTo, true), { replace: true });
    }

    window.addEventListener(SESSION_EXPIRED_EVENT, handleExpired);
    return function cleanup() {
      window.removeEventListener(SESSION_EXPIRED_EVENT, handleExpired);
    };
  }, [location.pathname, location.search, location.hash, navigate, queryClient]);

  return null;
}
```

过期后清除 CSRF、用户查询、项目缓存和 mutation 缓存，再跳登录。`cancelQueries` 会取消传入了 signal 的读取，世代编号也会阻止旧写请求的迟到响应进入新会话。

过期处理不需要、也不能通过 JavaScript 删除 HttpOnly Cookie；服务端已经判定它无效，重新登录会下发新 Cookie。主动退出则必须调用后端撤销会话。

```tsx
    onSuccess: function afterLogout() {
      clearSessionMemory();
      void queryClient.cancelQueries();
      queryClient.clear();
      navigate('/login', { replace: true });
    },
  });

  if (me.isPending) return <PageLoading />;

  if (me.isError) {
    if (me.error instanceof ApiError && me.error.code === 'SESSION_EXPIRED') {
      // /me 的未登录结果单独处理，清掉任何遗留内存和缓存。
      return <ExpiredSessionRedirect />;
    }
    return (
      <main className="page-shell">
        <RequestError error={me.error} onRetry={() => void me.refetch()} retrying={me.isFetching} />
      </main>
    );
  }

  const currentPath = `${location.pathname}${location.search}${location.hash}`;
  const returnTo = safeReturnTo(new URLSearchParams(location.search).get('returnTo'));
  if (me.data.user.mustChangePassword && location.pathname !== '/change-password') {
    return <Navigate to={`/change-password?returnTo=${encodeURIComponent(safeReturnTo(currentPath))}`} replace />;
  }
  if (!me.data.user.mustChangePassword && location.pathname === '/change-password') {
    return <Navigate to={returnTo} replace />;
  }

  return (
    <Layout className="app-layout">
      <Layout.Header className="app-header">
        <Typography.Title level={4}>工程标书工作台</Typography.Title>
        <Space wrap>
          <span>{me.data.organization.name} · {me.data.user.displayName}</span>
          <Button loading={logoutMutation.isPending} onClick={() => logoutMutation.mutate()}>
            退出登录
          </Button>
        </Space>
      </Layout.Header>
      <Layout.Content className="page-shell">
        {logoutMutation.isError && <RequestError error={logoutMutation.error} />}
        <Outlet context={me.data} />
      </Layout.Content>
    </Layout>
  );
}

function ExpiredSessionRedirect() {
  const location = useLocation();
  const queryClient = useQueryClient();
  const navigate = useNavigate();

  // 清缓存属于副作用，放在 effect 中，不能在 React 渲染期间修改。
  useEffect(() => {
    const returnTo = `${location.pathname}${location.search}${location.hash}`;
    clearSessionMemory();
    void queryClient.cancelQueries();
    queryClient.clear();
    navigate(loginUrl(returnTo, true), { replace: true });
  }, [location.pathname, location.search, location.hash, navigate, queryClient]);

  return <PageLoading />;
}
```

理解这个组件的判断顺序：先恢复 `/me` → 加载/错误 → 首次改密 → 显示项目界面。只有 `/me` 成功才允许业务页面挂载，刷新时不会抢先发送缺少 CSRF 的写请求。

退出请求失败时保留当前界面并提示，不能只跳登录就宣称会话已撤销。用户可以再次点击退出。

## 8. 第六步：新建项目弹窗

新增 `frontend/src/features/projects/CreateProjectModal.tsx`：

```tsx
import { useRef, useState } from 'react';
import { useMutation } from '@tanstack/react-query';
import { Alert, Form, Input, Modal, Select } from 'antd';
import { ApiError } from '../../api/errors';
import { createProject } from '../../api/projects';
import type { CreateProjectInput } from '../../api/projects';
import { RequestError } from '../../components/RequestError';

type CreateProjectModalProps = {
  onClose: () => void;
  onCreated: () => void;
};

type CreateAttempt = {
  fingerprint: string;
  key: string;
};

export function CreateProjectModal({ onClose, onCreated }: CreateProjectModalProps) {
  const [form] = Form.useForm<CreateProjectInput>();
  const submitting = useRef(false);
  const attempt = useRef<CreateAttempt | null>(null);
  const [succeeded, setSucceeded] = useState(false);
  const mutation = useMutation({
    mutationFn: function submitProject(values: CreateProjectInput) {
      const input = {
        ...values,
        name: values.name.trim(),
        constructionType: values.constructionType.trim(),
      };
      const fingerprint = JSON.stringify(input);
      if (!attempt.current || attempt.current.fingerprint !== fingerprint) {
        attempt.current = { fingerprint, key: crypto.randomUUID() };
      }
      return createProject(input, attempt.current.key);
    },
  });

  async function handleSubmit(values: CreateProjectInput): Promise<void> {
    if (submitting.current || succeeded) return;
    submitting.current = true;
    try {
      await mutation.mutateAsync(values);
      setSucceeded(true);
      onCreated();
    } catch {
      // 保留输入和本次 key，用户可以核对后重试。
    } finally {
      submitting.current = false;
    }
  }

  const uncertain = mutation.isError && mutation.error instanceof ApiError &&
    (mutation.error.status === 0 || mutation.error.status >= 500);

  return (
    <Modal
      open
      title="新建项目"
      okText="创建项目"
      cancelText="取消"
      confirmLoading={mutation.isPending}
      okButtonProps={{ disabled: succeeded }}
      cancelButtonProps={{ disabled: mutation.isPending }}
      closable={!mutation.isPending}
      maskClosable={false}
      keyboard={!mutation.isPending}
      onCancel={onClose}
      onOk={() => form.submit()}
    >
      {mutation.isError && <RequestError error={mutation.error} />}
      {uncertain && (
        <Alert type="warning" title="结果尚未确认。请保持内容不变重试；若关闭弹窗，请先刷新列表核对是否已创建。" />
      )}
      <Form<CreateProjectInput>
        form={form}
        layout="vertical"
        disabled={mutation.isPending || succeeded}
        initialValues={{ description: '', dataClassification: 'synthetic' }}
        onFinish={handleSubmit}
      >
        <Form.Item name="name" label="项目名称" rules={[{ required: true, whitespace: true, max: 200, message: '请输入项目名称，最多 200 字。' }]}>
          <Input maxLength={200} />
        </Form.Item>
        <Form.Item name="constructionType" label="工程类型" rules={[{ required: true, whitespace: true, max: 100, message: '请输入工程类型，最多 100 字。' }]}>
          <Input maxLength={100} placeholder="例如市政道路" />
        </Form.Item>
        <Form.Item name="description" label="项目描述" rules={[{ max: 2000, message: '最多 2000 字。' }]}>
          <Input.TextArea rows={4} maxLength={2000} showCount />
        </Form.Item>
        <Form.Item name="dataClassification" label="数据分类" rules={[{ required: true }]}>
          <Select options={[
            { value: 'synthetic', label: '模拟数据' },
            { value: 'deidentified', label: '脱敏数据' },
            { value: 'confidential', label: '保密数据' },
          ]} />
        </Form.Item>
      </Form>
    </Modal>
  );
}
```

这里为什么创建也带幂等键？后端允许可选键，前端主动使用，能应对“服务器创建成功，但浏览器没收到响应”。同一弹窗中相同内容复用键；内容改变生成新键，不违反后端摘要校验。

键存在内存中，关闭弹窗或刷新后就失去。因此提示用户先查列表，不承诺跨刷新重试仍幂等。`crypto.randomUUID()` 在本地可信回环地址或生产 HTTPS 下可用。

弹窗由父组件条件挂载，关闭时卸载整个表单，下次打开是新的组件实例；不用额外依赖 Modal 的销毁配置。AntD 表单与弹窗有独立保留行为，参考 [Form](https://ant.design/components/form/) 与 [Modal](https://ant.design/components/modal/)。

## 9. 第七步：归档确认弹窗

新增 `frontend/src/features/projects/ArchiveProjectModal.tsx`：

```tsx
import { useRef, useState } from 'react';
import { useMutation } from '@tanstack/react-query';

import { ApiError } from '../../api/errors';
import { archiveProject } from '../../api/projects';

type ArchiveProjectModalProps = {

  onClose: () => void;
  onArchived: () => void;
  onRefresh: () => void;
};

export function ArchiveProjectModal({ project, onClose, onArchived, onRefresh }: ArchiveProjectModalProps) {
  const [key] = useState(() => crypto.randomUUID());
  const submitting = useRef(false);
  const [succeeded, setSucceeded] = useState(false);

    mutationFn: function submitArchive() {

    submitting.current = true;
    try {
      await mutation.mutateAsync();
      setSucceeded(true);
      onArchived();
    } catch {
      // 保留弹窗、原版本号和 key，不擅自覆盖他人的更新。
    } finally {
      submitting.current = false;
    }
  }

  return (
    <Modal
      open
      title="确认归档项目"
      okText="确认归档"
      cancelText="取消"
      okButtonProps={{ danger: true, disabled: conflict || succeeded }}
      confirmLoading={mutation.isPending}
      cancelButtonProps={{ disabled: mutation.isPending }}
      closable={!mutation.isPending}
      maskClosable={false}
      keyboard={!mutation.isPending}
      onOk={() => void handleArchive()}
      onCancel={onClose}
    >
      <Typography.Paragraph>即将归档：<strong>{project.name}</strong></Typography.Paragraph>
      <Typography.Paragraph>
        归档后项目只读，保留历史内容；不能继续编辑、上传、生成或审核。本页不提供恢复操作。
      </Typography.Paragraph>
      {mutation.isError && <RequestError error={mutation.error} />}
      {conflict && <Button onClick={onRefresh}>刷新列表后重新确认</Button>}
      {mutation.isError && !conflict && (
        <Alert type="info" title="如果是网络错误，请保留当前弹窗，稍后再次确认会使用同一个操作编号。" />
      )}
    </Modal>
  );
}
```

`project` 是用户点击归档时的快照。发生冲突后禁用原确认按钮，让用户关闭弹窗、刷新列表、阅读新数据，再重新决定归档；不能拿错误里的新版本号自动覆盖重试。

普通网络重试仍使用同一个 key 和同一个版本号。刷新后重新确认属于新的业务意图，生成新 key。不要每点击一次就生成新 key，否则响应丢失后的重试失去保护。

```tsx
      </Space>

      {query.isError && (
        <RequestError error={query.error} onRetry={() => void query.refetch()} retrying={query.isFetching} />
      )}

      <Table<Project>
        rowKey="id"
        columns={columns}
        dataSource={query.data?.items ?? []}
        loading={query.isFetching}
        pagination={false}
        scroll={{ x: 760 }}
        locale={{
          emptyText: query.isError
            ? '列表未能加载，请点击上方重试。'
            : query.isPending
              ? '正在加载项目……'
              : <Empty description={q || status !== 'active'
                ? '没有符合条件的项目，请调整筛选。'
                : canCreate
                  ? '还没有项目，点击右上角新建一个。'
                  : '还没有项目，请联系管理员或编写者创建。'} />,
        }}
      />

      <Space className="pagination-bar" wrap>
        <Button disabled={paging.previous.length === 0 || query.isFetching} onClick={goPrevious}>上一页</Button>
        <span>第 {paging.previous.length + 1} 页</span>
        <Button disabled={!query.data?.hasMore || !query.data.nextCursor || query.isFetching || query.isError} onClick={goNext}>下一页</Button>
      </Space>

      {createOpen && <CreateProjectModal onClose={() => setCreateOpen(false)} onCreated={handleCreated} />}
      {archiveTarget && (
        <ArchiveProjectModal
          project={archiveTarget}
          onClose={() => setArchiveTarget(null)}
          onArchived={handleArchived}
          onRefresh={refreshAfterConflict}
        />
      )}
    </section>
  );
}
```

### 10.1 为什么不用表格自带页码分页

后端返回的是不透明游标，没有 `total`。前端不能假装知道“共 100 页”，不能把 page=2 当 cursor，更不能解析或拼造后端游标。

这里用 `previous` 栈记住访问过的游标：第一页 cursor=null → 下一页压入 null → 再下一页压入当前 cursor → 上一页从栈中取出。界面的“第 N 页”只是本次浏览的相对位置，不是数据库页号。

后端按 `created_at DESC, id DESC` 排序，更新时间只是显示字段，不能在前端按更新时间重新排列当前页，否则跨页顺序会混乱。

### 10.2 筛选与刷新规则

- 输入时只更新 `searchText`，按回车、搜索按钮或清除按钮才提交 `q`。
- q、status 改变后重置 cursor 栈，因为后端游标与过滤条件绑定。
- 新建后清空搜索、切回进行中、回第一页，避免新项目被当前筛选隐藏。
- 归档后回第一页并让相关查询失效，避免删去最后一行后停在空的后续页。
- queryKey 包含组织、用户、过滤条件和 cursor，防止不同列表共享错误缓存。
- 失败时不能把“请求失败”误显示成“你还没有项目”；如果有旧数据，错误提示与旧表格可以同时出现。

### 10.3 前端隐藏按钮不是安全边界

reviewer 看不到新建按钮，writer 看不到可操作的归档按钮，这是交互优化。真正授权仍由后端执行；用户自行构造 HTTP 请求也必须被拒绝。

### 11.2.1 串起来理解一次刷新和一次创建

刷新 `/projects` 时：

1. 浏览器下载 `index.html` 和前端资源，运行 `main.tsx`。
2. BrowserRouter 匹配 `/projects`，先挂载 `ProtectedLayout`。
3. `useQuery` 调用 `getMe(signal)`，浏览器自动带 Cookie。
4. 后端确认会话，返回用户摘要、组织摘要、CSRF Token。
5. `auth.ts` 转换字段、把 CSRF 留在内存；Query 保存用户摘要。
6. 通过首次改密检查后，`Outlet` 才挂载 `ProjectsPage`。
7. 项目 Query 发出带游标/筛选参数的 GET，请求成功后渲染表格。

点击创建时：

1. `createOpen=true`，React 挂载新建弹窗。
2. 点击“创建项目”调用 `form.submit()`，AntD 先执行表单规则。
3. 校验通过才调用 `handleSubmit`，ref 锁和 mutation loading 阻止重复提交。
4. API 模块将 camelCase 变成 snake_case，客户端带 CSRF 和本次幂等键。
5. 后端依据 Cookie 的真实身份检查权限，事务中保存项目与默认五章。
6. 收到 201 后关闭弹窗、回第一页、清筛选并让列表查询失效。
7. Query 重新读取后端列表，表格出现新项目。

因此项目持久化的原因是第 5 步写入数据库；Query 缓存只是减少页面管理负担，不是数据库，也不负责跨刷新保存。

## 13. 第十一步：认真验收不顺利的情况

| 场景 | 怎样操作 | 应看到什么 |
|---|---|---|
| 密码错误 | 输入一次错误密码，避免连续五次触发锁定 | 登录页明确失败，按钮恢复，密码清空，留在登录页 |
| 请求变慢 | DevTools Network 选择 Slow 3G | 加载反馈，写按钮显示提交中，不能重复提交 |
| 首次改密 | 使用 `must_change_password=true` 账号登录 | 先显示改密页，成功后进入项目列表 |
| 空列表 | 独立空组织或搜索不存在名称 | 引导或无匹配提示，不显示技术错误 |
| 后端不可达 | 保持 Vite 运行，停止 uvicorn 后刷新 | `/me` 请求失败，出现错误与重试；恢复后重试有效 |
| 会话过期 | DevTools Application 中删除 `bid_session`，再点刷新列表 | 清内存和项目缓存，跳登录，显示过期原因，登录后返回 |
| 无权限 | reviewer 登录；writer 验证归档权限 | reviewer 无新建；writer 无可点击归档；后端仍执行授权 |
| 非 JSON 错误 | 后端停止导致代理错误 | 显示服务暂时不可用，不显示 HTML 或 `Unexpected token` |
| 版本冲突 | 一个窗口打开归档弹窗，另一个窗口修改项目版本 | 原窗口归档收到 409，提示刷新，不能直接强制归档 |
| 幂等重试 | 开发时拦截/丢弃创建或归档响应，再用原弹窗重试 | 同 key、同 payload，不重复创建；归档可重放 |
| 游标 | 独立演示库建立超过 20 个项目 | 上下页正常，改变筛选回第一页，没有假总页数 |
| 退出失败 | 停止后端，再点退出 | 提示退出未完成，不声称已撤销远端会话 |

### 13.1 手动构造版本冲突，不用改应用代码

用两个窗口分别登录同组织 admin。A 窗口打开归档确认，不确认；B 窗口按 F12 在 Console 执行下面代码，先把项目 ID 替换成列表响应里的真实 ID：

```js
const projectId = '替换为真实项目UUID';
const meResponse = await fetch('/api/v1/auth/me', { credentials: 'same-origin' });
const meBody = await meResponse.json();
const projectResponse = await fetch(`/api/v1/projects/${projectId}`, { credentials: 'same-origin' });
const projectBody = await projectResponse.json();
const updateResponse = await fetch(`/api/v1/projects/${projectId}`, {
  method: 'PATCH',
  credentials: 'same-origin',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-Token': meBody.data.csrf_token,
  },
  body: JSON.stringify({
    expected_lock_version: projectBody.data.lock_version,
    description: `A7 版本冲突练习 ${Date.now()}`,
  }),
});
console.log(updateResponse.status);
```

B 成功后，A 再确认归档应提示“数据已经被其他人修改，请刷新后重试”。这是本地演示数据练习；不要打印 Cookie、CSRF 或整个认证响应。

### 13.2 “断网刷新”必须分成两种情况

**接口不可用但页面资源还能加载：** 保持 Vite 或静态站点入口可达，停止 API，再刷新 `/projects`。本教程会显示 `/me` 错误与重试，不白屏。

**页面已加载后断网：** React 已经运行，offline 提示会出现；列表刷新或写请求失败也会进入可见错误。

**浏览器完全离线后硬刷新，连 HTML/JS 都下载不到：** React 根本没机会运行，这时普通 SPA 只能显示浏览器的离线错误页。仅靠 React 错误组件不能解决。若验收要求此时仍显示自定义应用页面，需要额外做 Service Worker 缓存应用壳或 PWA 离线页，并约定首次在线加载与升级策略；这超出本次 A7 的最小实现。

不能声称本教程完成了完整离线应用。服务工作线程也不应把认证响应和敏感项目内容随意离线持久化。

## 16. 为什么身份凭证不能放 localStorage

会话凭证相当于登录后的通行证。localStorage 可被同源 JavaScript 读取，一旦页面存在 XSS，恶意脚本就可能把它复制并带走；关页面后它仍然保留，也增加误用、误分享和跨账号残留风险。

HttpOnly Cookie 不允许 JavaScript 通过 `document.cookie` 读取会话值，浏览器按 Cookie 规则自动携带；生产再加 Secure，通过 HTTPS 传输。这个浏览器行为可查 [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)。

但 HttpOnly 不是“彻底免疫 XSS”：恶意脚本仍可能在当前页面发请求。因此还需要正确输出转义、依赖管理、服务端权限与 CSRF/Origin 检查，不能因为 HttpOnly 就把原始 HTML 随便插进页面。

本项目的区别要记住：

| 信息 | 存在哪里 | 前端怎么使用 |
|---|---|---|
| `bid_session` 会话凭证 | 浏览器 HttpOnly Cookie；服务端保存关联会话 | 浏览器自动带，JS 不读取 |
| CSRF Token | 前端内存；刷新由 `/me` 恢复 | 写请求加 `X-CSRF-Token`，不是独立登录凭证 |
| 当前用户、组织摘要 | Query 内存缓存 | 展示与交互控制，不能替代服务端授权 |
| 项目数据 | PostgreSQL；前端有临时查询缓存 | 刷新重新查询，持久化靠后端 |
| 数据库密码、CSRF 签名密钥 | 后端配置 | 永远不放到 `VITE_*` 或前端包里 |

CSRF Token 返回给前端是设计的一部分；HttpOnly 会话值不返回给 JavaScript。两者不能混为“所有 Token 都不能被前端接触”。

## 17. 常见报错与定位顺序

| 问题 | 优先排查 |
|---|---|
| `npm` 在错误目录运行 | 当前目录应为 `frontend`，那里有 package.json |
| Vite 提示端口占用 | 停掉旧进程；保持 5173 与 Origin 配套，不随意切端口 |
| 登录 403 | 请求 Origin、`SECURITY__PUBLIC_ORIGIN`、是否真的重启后端 |
| 登录成功后立刻 401 | Cookie 是否保存、是否 `ENV=prod` 导致 HTTP 下 Secure Cookie 不可用、主机名是否混用 |
| 登录后项目 403 | `PASSWORD_CHANGE_REQUIRED` 先改密，或检查角色权限 |
| 刷新后写请求没有 CSRF | `/me` 是否成功；写页面是否放在 ProtectedLayout 下 |
| 创建 422 | 必填/长度、snake_case、description 不要传 null、不要额外传 org_id |
| 归档 422 | 是否携带长度合规的 Idempotency-Key 和整数版本号 |
| 归档 409 | 看稳定 error.code，区分版本冲突、已归档、处理中和运行未结束 |
| `title` 属性类型不匹配 | 检查是否装成 antd 5；本文使用 antd 6 |
| Hook 规则报错 | Hook 是否位于组件顶层，是否放进判断、事件或普通嵌套函数 |
| build 找不到类型 | 核对文件名大小写、导入路径、是否复制完整 type 定义 |
| 搜索后下一页 422 | 改筛选时是否清空旧 cursor，不要解析服务端游标 |
| 构建成功但刷新 404 | 生产入口缺少 SPA 的 index.html 回退，或错误地把 API 当静态页面 |
| 完全断网后硬刷新浏览器报错 | 页面资源都不可达，不是 React 请求错误；需要另做应用壳缓存 |

定位习惯：先看浏览器 Network 的 URL、状态码与结构化 error.code，再拿 request_id 查后端日志。不要只看 Console 红字，也不要为了“让请求通过”关闭后端 Origin、CSRF、权限或租户检查。
