### 1.5 这份教程怎样保持你的代码风格

- 所有 Pydantic 模型字段都写成 `字段: 类型 = Field(...)`，包括请求、响应和内部游标模型。Field 中提供中文 description，并按字段含义声明默认值和适用约束；枚举继续使用 Literal。
- 路由先取出请求字段，逐项传给服务，再用 `data` 或 `result` 接住结果；服务不直接接收整个 HTTP 请求模型。
- 参数较多的定义和调用分行展开，保留尾逗号；SQL 查询继续使用 `select(...).where(...)` 和 `update(...).values(...)` 的链式写法。
- 函数开头补简短中文说明，关键事务和并发步骤补注释，使用空行区分业务步骤。
- 分页和幂等需要回调时使用具名函数，让你能按函数名找到执行逻辑。

## 2. 第一步：补齐公共响应、异常和请求日志

### 2.1 先理解三种错误

- 业务错误：例如版本冲突。由服务抛出 `ApiError`，它携带稳定错误码。
- 参数错误：例如版本号为 0。Pydantic/FastAPI 抛出校验异常，统一返回 422。
- 程序错误：例如意外的 `RuntimeError`。记录服务端堆栈，客户端只看到统一的 500。

错误处理器只负责“翻译异常”，不应该在那里查询项目、重试事务或更改数据。

### 2.2 扩展 ApiError

手动替换 `backend/app/core/errors.py`，完整内容：

```python
from typing import Any


class ApiError(Exception):
    """业务错误：状态码、稳定错误码、提示、详情与响应头。"""

    def __init__(
        self,
        status_code: int,
        code: str,
        message: str,
        *,
        details: dict[str, Any] | None = None,
        retryable: bool = False,
        headers: dict[str, str] | None = None,
    ) -> None:
        super().__init__(message)
        self.status_code = status_code
        self.code = code
        self.message = message
        self.details = details or {}
        self.retryable = retryable
        self.headers = headers or {}
```

`retryable=True` 表示客户端可以稍后重试，不表示服务器自动重做。`Retry-After` 是 HTTP 头，不能只把它写在错误说明里。

### 2.3 统一错误处理

手动替换 `backend/app/api/errors.py`，完整内容：

```python
import logging
import uuid
from collections.abc import Mapping
from typing import Any

from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from starlette.exceptions import HTTPException

from backend.app.core.errors import ApiError

logger = logging.getLogger("uvicorn.error")


def request_id_of(request: Request) -> str:
    """获取本次请求编号；没有则生成并写回请求状态。"""

    value = getattr(
        request.state,
        "request_id",
        None,
    )
    if not isinstance(value, str):
        value = str(uuid.uuid4())
        request.state.request_id = value
    return value


def ok(request: Request, data: dict[str, Any]) -> dict[str, Any]:
    """包装成功响应，所有普通业务接口使用同一种外壳。"""

    return {"data": data, "request_id": request_id_of(request)}


def error_response(
    request: Request,
    status_code: int,
    code: str,
    message: str,
    *,
    details: dict[str, Any] | None = None,
    retryable: bool = False,
    headers: Mapping[str, str] | None = None,
) -> JSONResponse:
    """包装错误响应，同时保留请求编号和业务需要的响应头。"""

    response_headers = dict(headers or {})
    response_headers["X-Request-ID"] = request_id_of(request)
    return JSONResponse(
        status_code=status_code,
        headers=response_headers,
        content={
            "error": {
                "code": code,
                "message": message,
                "details": details or {},
                "retryable": retryable,
            },
            "request_id": request_id_of(request),
        },
    )


async def api_error_handler(request: Request, exc: Exception) -> JSONResponse:
    """把 ApiError 转换成统一的 JSON 错误响应。"""

    if not isinstance(exc, ApiError):
        return await unexpected_error_handler(request, exc)
    return error_response(
        request,
        exc.status_code,
        exc.code,
        exc.message,
        details=exc.details,
        retryable=exc.retryable,
        headers=exc.headers,
    )


async def validation_error_handler(request: Request, exc: Exception) -> JSONResponse:
    """把请求校验错误转换成 details.fields 字段列表。"""

    fields: list[dict[str, str]] = []
    if isinstance(exc, RequestValidationError):
        fields = [
            {
                "field": ".".join(str(part) for part in err["loc"] if part != "body"),
                "reason": err["msg"],
            }
            for err in exc.errors()
        ]
    return error_response(
        request,
        422,
        "VALIDATION_ERROR",
        "请求字段不合法",
        details={"fields": fields},
    )


async def http_error_handler(request: Request, exc: Exception) -> JSONResponse:
    """统一处理框架产生的 404、405 等 HTTP 错误。"""

    if not isinstance(exc, HTTPException):
        return await unexpected_error_handler(request, exc)
    codes = {404: "RESOURCE_NOT_FOUND", 405: "METHOD_NOT_ALLOWED"}
    messages = {404: "资源不存在", 405: "请求方法不支持"}
    return error_response(
        request,
        exc.status_code,
        codes.get(exc.status_code, "HTTP_ERROR"),
        messages.get(exc.status_code, "请求无法完成"),
        headers=exc.headers,
    )


async def unexpected_error_handler(request: Request, exc: Exception) -> JSONResponse:
    """服务端记录未知异常，客户端只收到安全的 500 响应。"""

    logger.error(
        "unhandled_error request_id=%s method=%s path=%s",
        request_id_of(request),
        request.method,
        request.url.path,
        exc_info=(type(exc), exc, exc.__traceback__),
    )
    return error_response(
        request,
        500,
        "INTERNAL_ERROR",
        "服务器内部错误",
    )


def install_error_handlers(app: FastAPI) -> None:
    """集中注册异常处理器，避免路由各写一套错误格式。"""

    app.add_exception_handler(ApiError, api_error_handler)
    app.add_exception_handler(RequestValidationError, validation_error_handler)
    app.add_exception_handler(HTTPException, http_error_handler)
    app.add_exception_handler(Exception, unexpected_error_handler)
```

原来的处理器虽然有“非 ApiError 就返回 500”的分支，但只注册了 `ApiError`，普通异常不会因此自动进入它。这次显式补齐注册。

`HTTPException` 从 Starlette 导入，能覆盖框架产生的 404/405。不要直接把 `exc.detail` 全部返回给客户端，那里可能带内部信息。`INTERNAL_ERROR`、`METHOD_NOT_ALLOWED`、`HTTP_ERROR` 属于需要补进错误码文档的公共兜底码。

### 2.4 请求中间件和日志

手动替换 `backend/app/api/middleware.py`，完整内容：

```python
import logging
import time
import uuid

from starlette.middleware.base import BaseHTTPMiddleware, RequestResponseEndpoint
from starlette.requests import Request
from starlette.responses import Response

from backend.app.api.errors import error_response, unexpected_error_handler
from backend.app.core.settings import settings

logger = logging.getLogger("uvicorn.error")
UNSAFE_METHODS = frozenset({"POST", "PUT", "PATCH", "DELETE"})


class RequestIdMiddleware(BaseHTTPMiddleware):
    """给每个请求生成独立编号，并记录开始、结束和异常日志。"""

    async def dispatch(
        self,
        request: Request,
        call_next: RequestResponseEndpoint,
    ) -> Response:
        request.state.request_id = str(uuid.uuid4())
        started = time.perf_counter()
        logger.info(
            "request_started request_id=%s method=%s path=%s",
            request.state.request_id,
            request.method,
            request.url.path,
        )
        try:
            response = await call_next(request)
        except Exception as exc:
            # 未知异常可能穿过用户中间件，到外层 ServerErrorMiddleware。
            # 在这里兜底，保证普通 JSON 接口的 500 也有本次编号和响应头。
            response = await unexpected_error_handler(request, exc)
        response.headers["X-Request-ID"] = request.state.request_id
        logger.info(
            "request_finished request_id=%s method=%s path=%s status=%s duration_ms=%.2f",
            request.state.request_id,
            request.method,
            request.url.path,
            response.status_code,
            (time.perf_counter() - started) * 1000,
        )
        return response


class OriginCheckMiddleware(BaseHTTPMiddleware):
    """浏览器写请求校验来源；命令行不带 Origin 时继续执行。"""

    async def dispatch(
        self,
        request: Request,
        call_next: RequestResponseEndpoint,
    ) -> Response:
        if request.method in UNSAFE_METHODS:
            origin = request.headers.get("origin")
            if origin is not None and origin != settings.security.public_origin:
                return error_response(
                    request,
                    403,
                    "CSRF_INVALID",
                    "请求来源不被信任",
                )
        return await call_next(request)
```

保留 `main.py` 当前的注册顺序：先 `OriginCheckMiddleware`，再 `RequestIdMiddleware`。后添加的用户中间件在外面执行，因此非法 Origin 的响应也能带请求编号。

日志只记方法、路径、编号、状态、耗时；不记请求体、查询原文、Cookie、CSRF Token 或幂等原始键。当前复用 Uvicorn 的日志配置，所以启动后能看到这些 INFO 日志。以后 SSE 的流已开始后发生异常，不能再替换 HTTP 响应，这属于 A8 专门处理的范围。

### 2.5 声明成功响应模型

新建 `backend/app/api/schemas.py`，完整内容：

```python
from pydantic import BaseModel, Field


class SuccessResponse[T](BaseModel):
    """统一成功响应：具体业务数据和请求编号。"""

    data: T = Field(
        ...,
        description="本次请求的业务数据，具体结构由接口的响应模型决定",
    )
    request_id: str = Field(
        ...,
        min_length=36,
        max_length=36,
        pattern=r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$",
        description="请求 UUID；幂等重放时保留首次响应中的编号，本次编号见 X-Request-ID",
    )


class CursorPage[T](BaseModel):
    """游标分页结果：当前页数据、下一页游标和是否还有数据。"""

    items: list[T] = Field(
        ...,
        max_length=100,
        description="当前页的数据列表，空结果返回空数组，每页最多 100 条",
    )
    next_cursor: str | None = Field(
        ...,
        min_length=1,
        max_length=2048,
        description="下一页游标；没有下一页时必须返回 null，不能省略字段",
    )
    has_more: bool = Field(
        ...,
        strict=True,
        description="是否还有下一页；true 时 next_cursor 应提供下一页游标",
    )
```

`T` 是“这里以后填具体类型”的占位符。`SuccessResponse[ProjectResponse]` 代表项目详情，`SuccessResponse[CursorPage[ProjectResponse]]` 代表项目列表。这是 Python 3.12 支持的泛型写法，与你的 Ruff 目标版本一致。

这里的 `Field(...)` 中，三个点是 Python 的 Ellipsis，表示字段必填。例如 next_cursor 的类型允许 None，但 `Field(...)` 要求响应必须带这个字段；最后一页应返回 `"next_cursor": null`，不能直接省略。items 不设默认空列表，也是为了让遗漏列表字段的实现及时报错。max_length=100 对列表表示最多 100 个元素，与通用分页上限一致。

data 的具体约束交给泛型参数中的模型，例如 ProjectResponse。不要给泛型数据随意加字符串长度或整数范围限制。request_id 则是字符串，因此明确校验 UUID 文本长度与格式。

现有认证和成员路由继续调用 `ok()`。本次只给项目路由补具体响应模型，后续模块照此使用。错误外壳由全局处理器统一；响应模型不会自动把所有错误结构加入 OpenAPI，需要在做完整 API 合同门禁时再统一声明 `responses`。

**本节检查：** 能解释为什么服务只抛异常、为什么未知异常不能回传堆栈、为什么请求编号中间件必须在 Origin 校验外面。

## 3. 第二步：实现稳定游标分页

### 3.1 游标里到底放什么

假设一页最后一条是 `(2026-10-11T08:00:00Z, UUID-X)`，下一页条件为：

```sql
WHERE org_id = :org_id
  AND (created_at, id) < (:last_created_at, :last_id)
ORDER BY created_at DESC, id DESC
LIMIT :limit_plus_one;
```

`<` 对应降序列表的“后面”。如果只有时间而没有 UUID，相同时间的一批项目可能被遗漏。

多取一条用于判断 `has_more`。用户要 20 条就查询 21 条：返回前 20 条，用第 20 条生成下一页游标。不能用第 21 条作为锚点，否则会漏掉它。

游标里同时保存过滤条件摘要，绑定组织、用户、列表类型、q 和 status。改变 q 或 status 后继续使用旧游标，返回 422。limit 不是过滤条件，允许翻页时修改大小。

### 3.2 新增公共分页模块

新建 `backend/app/core/pagination.py`，完整内容：

```python
import base64
import binascii
import hashlib
import json
import uuid
from collections.abc import Callable, Sequence
from dataclasses import dataclass
from datetime import UTC, datetime

from pydantic import BaseModel, ConfigDict, Field, ValidationError

from backend.app.core.errors import ApiError


@dataclass(frozen=True)
class CursorAnchor:
    """上一页最后一条记录的位置，由时间和 UUID 共同确定。"""

    created_at: datetime
    id: uuid.UUID


class CursorPayload(BaseModel):
    """游标内保存的字段，拒绝未定义字段和错误类型。"""

    model_config = ConfigDict(extra="forbid", strict=True)

    version: int = Field(
        ...,
        ge=1,
        le=1,
        description="游标编码格式版本，当前只支持整数 1",
    )
    filters_hash: str = Field(
        ...,
        min_length=64,
        max_length=64,
        pattern=r"^[0-9a-f]{64}$",
        description="组织、用户、资源类型与查询条件的 SHA-256 摘要，小写十六进制",
    )
    created_at: str = Field(
        ...,
        min_length=1,
        description="上一页最后一条记录的 UTC ISO 8601 时间；解析时还会检查时间格式和时区",
    )
    id: str = Field(
        ...,
        min_length=36,
        max_length=36,
        pattern=r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$",
        description="上一页最后一条记录的 UUID，与 created_at 一起组成稳定排序锚点",
    )


def canonical_json(value: object) -> str:
    """统一 JSON 键顺序和分隔符，供摘要计算使用。"""

    return json.dumps(
        value,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
    )


def filters_digest(filters: dict[str, object]) -> str:
    """计算过滤条件摘要，防止修改条件后继续使用旧游标。"""

    return hashlib.sha256(canonical_json(filters).encode("utf-8")).hexdigest()


def encode_cursor(anchor: CursorAnchor, filters: dict[str, object]) -> str:
    """将排序锚点和过滤摘要编码成客户端携带的游标。"""

    payload = {
        "version": 1,
        "filters_hash": filters_digest(filters),
        "created_at": anchor.created_at.astimezone(UTC).isoformat(),
        "id": str(anchor.id),
    }
    payload_json = canonical_json(payload)
    payload_bytes = payload_json.encode("utf-8")
    encoded = base64.urlsafe_b64encode(payload_bytes)
    return encoded.decode("ascii").rstrip("=")


def decode_cursor(cursor: str | None, filters: dict[str, object]) -> CursorAnchor | None:
    """解析并检查游标，无效或条件变化时返回 422。"""

    if cursor is None:
        return None
    try:
        if not cursor or len(cursor) > 2048:
            raise ValueError("cursor length")
        raw = base64.b64decode(
            cursor + "=" * (-len(cursor) % 4),
            altchars=b"-_",
            validate=True,
        )
        payload = CursorPayload.model_validate_json(raw)
        if payload.version != 1 or payload.filters_hash != filters_digest(filters):
            raise ValueError("cursor scope")
        created_at = datetime.fromisoformat(payload.created_at)
        if created_at.tzinfo is None or created_at.utcoffset() is None:
            raise ValueError("timezone required")
        return CursorAnchor(created_at=created_at, id=uuid.UUID(payload.id))
    except (ValueError, ValidationError, binascii.Error) as exc:
        raise ApiError(
            422,
            "VALIDATION_ERROR",
            "游标无效或过滤条件已改变",
            details={"fields": [{"field": "cursor", "reason": "请从第一页重新查询"}]},
        ) from exc


def paginate[T](
    *,
    limit: int = 20,
    cursor: str | None,
    filters: dict[str, object],
    fetch: Callable[[CursorAnchor | None, int], Sequence[T]],
    anchor_of: Callable[[T], CursorAnchor],
) -> tuple[list[T], str | None, bool]:
    """多查询一条判断下一页，只把用户请求的数量作为当前页返回。"""

    if not 1 <= limit <= 100:
        raise ApiError(
            422,
            "VALIDATION_ERROR",
            "limit 必须在 1 到 100 之间",
        )
    anchor = decode_cursor(cursor, filters)
    rows = list(fetch(anchor, limit + 1))
    has_more = len(rows) > limit
    items = rows[:limit]
    next_cursor = None
    if has_more:
        last_item = items[-1]
        next_anchor = anchor_of(last_item)
        next_cursor = encode_cursor(next_anchor, filters)
    return items, next_cursor, has_more
```

这里公共工具不依赖 `Project`，只通过两个函数协作：`fetch()` 根据锚点查数据库，`anchor_of()` 从记录提取时间和 ID。以后文档列表也可以复用它；章节按 position 排序，需要另写对应锚点，不能套用时间排序。

Base64 是编码，不是加密或签名。这份合同只要求编码摘要和锚点；游标不能代替组织过滤和 RLS，客户端即使构造自己的合法锚点也只能访问自己有权读取的数据。如果未来需要防篡改，另加独立的签名密钥，不复用 CSRF 密钥。

CursorPayload 也要用 Field：version 目前限定为 1，filters_hash 限定为 64 位小写十六进制，id 限定为标准 UUID 文本。created_at 除了 Field 的非空约束，还会在 decode_cursor 中转换成 datetime 并检查时区；仅写 description 不会自动执行时间格式校验。

**稳定性的范围：** 新增时间更晚的项目不会让已翻过的数据重复出现；游标分页不等于跨请求数据库快照。如果项目被删除、归档或改名导致不再匹配过滤，结果集合也会变化。这是动态列表的正常边界。

```python
    op.execute("DROP TABLE app.chapters")
```

- `ops` schema 在 A5 已存在，不能在 downgrade 中删除它。
- app_runtime 只能 SELECT/INSERT/UPDATE 幂等记录，没有 DELETE 权限。过期记录在这里通过更新复用，批量清理由维护角色完成。

- ops_runtime 不能读幂等响应。业务服务不能使用 `OpsSessionLocal` 写幂等表。
- SQL 默认外键删除策略为 NO ACTION，禁止直接删被引用父记录；与你当前 Project 风格一致，没有级联删除业务成果。

理解 `model_fields_set`：PATCH 中“没有提交 description”代表保持原值，“提交 description 为空字符串”代表清空描述；它们不同。字段可选不代表数据库可存 NULL。这里通过校验拒绝显式 null。

字段约束仍使用你熟悉的 `Field()`。新增的 `field_validator(..., mode="before")` 在字段长度校验之前运行，只去掉名称和工程类型两端的空白。它的参数用 object，是因为这时传入值还没有完成类型校验；只有字符串才调用 strip，其他值继续交给 Pydantic 判断。

所有请求字段和响应字段都补齐了 Field；可以按下面的分工理解：

| 写法 | 作用 |
|---|---|
| `description="项目名称"` | 说明字段用途，会显示在 OpenAPI 和 Swagger 中，本身不执行校验 |
| `Field(...)` | 字段必填，不能省略；能否为 null 仍由类型决定 |
| `default=""` / `default="synthetic"` | 创建时可以省略，由模型补上约定的默认值 |
| `default=None` | PATCH 中允许省略字段；显式提交 null 仍由 check_changes 拒绝 |
| `min_length` / `max_length` | 限制字符串字符数，或列表元素个数 |
| `ge=1` / `strict=True` | 限制版本号为正整数，拒绝把字符串或布尔值转换成版本号 |
| `pattern` | 校验字符串格式，例如请求编号和摘要 |
| `uuid.UUID` / `Literal[...]` | 类型本身校验 UUID 或允许的枚举值，Field 再补充业务说明 |

ProjectResponse 中的 current_baseline_id 是“必填且可空”，PATCH 中的 name 是“可以省略，但提交后不能为 null”，两种含义不能混在一起。响应字段也不随意设置默认值，否则服务漏返回 lock_version 等字段时可能被默认值掩盖。

Field 负责单字段说明和约束；“PATCH 至少修改一个字段”由 model_validator 检查，“归档项目只读”和“版本必须匹配数据库当前值”由服务与数据库检查。时间字段的类型 datetime 校验时间值，UTC 输出由 utc_text 保证，description 只是对这个约定的说明。

model_config 是模型配置，不是请求或响应字段，不使用 Field。WriteResult、CursorAnchor 等 dataclass 也不是 Pydantic BaseModel，它们继续使用普通类型注解。

`expected_lock_version` 用 strict=True，避免把 JSON 的 true 或字符串 `"1"` 当整数版本。列表返回的 lock_version 仍是普通整数。

名称和工程类型去掉两端空白、拒绝纯空格，是对文档长度约束的细化，需要在最终回写中说明。描述保留用户输入的空白和换行。

旧 `UpdateProjectDescriptionRequest` 将被替换。后面路由和服务也一起换，不能留着旧导入。原 A5 HTTP 测试仍提交合法的 description + expected_lock_version，不受影响。

```python
import uuid
from collections.abc import Sequence
from typing import Any

from sqlalchemy import func, select, tuple_, update
from sqlalchemy.orm import Session

from backend.app.core.pagination import CursorAnchor
from backend.app.models.chapters import Chapter
from backend.app.models.projects import Project


def find_project(
    db: Session,
    *,
    org_id: uuid.UUID,
    project_id: uuid.UUID,
) -> Project | None:
    """按组织和项目编号查询，同时刷新 Session 中可能缓存的旧值。"""

    return db.execute(
        select(Project)
        .where(
            Project.org_id == org_id,
            Project.id == project_id,
        )
        .execution_options(populate_existing=True)
    ).scalar_one_or_none()


def fetch_projects(
    db: Session,
    *,
    org_id: uuid.UUID,
    q: str | None,
    status: str | None,
    anchor: CursorAnchor | None,
    size: int,
) -> Sequence[Project]:
    """按过滤条件和排序锚点查询项目，不在仓储内提交事务。"""

    statement = select(Project).where(Project.org_id == org_id)
    if q is not None:
        # autoescape 将 % 和 _ 作为普通字符，避免查询意外变成通配符。
        statement = statement.where(Project.name.icontains(q, autoescape=True))
    if status is not None:
        statement = statement.where(Project.status == status)
    if anchor is not None:
        statement = statement.where(
            tuple_(Project.created_at, Project.id) < tuple_(anchor.created_at, anchor.id)
        )
    return (
        db.execute(statement.order_by(Project.created_at.desc(), Project.id.desc()).limit(size))
        .scalars()
        .all()
    )


def update_project_if_version_matches(
    db: Session,
    *,
    org_id: uuid.UUID,
    project_id: uuid.UUID,
    expected_lock_version: int,
    changes: dict[str, Any],
) -> Project | None:
    """版本和状态匹配才更新，返回 None 表示没有记录满足条件。"""

    return db.execute(
        update(Project)
        .where(
            Project.org_id == org_id,
            Project.id == project_id,
            Project.lock_version == expected_lock_version,
            Project.status == "active",
        )
        .values(
            **changes,
            lock_version=Project.lock_version + 1,
            updated_at=func.now(),
        )
        .returning(Project)
        .execution_options(populate_existing=True)
    ).scalar_one_or_none()


def mark_chapters_for_review(
    db: Session,
    *,
    org_id: uuid.UUID,
    project_id: uuid.UUID,
) -> None:
    # 这是项目修改带来的服务端失效操作，版本在数据库中逐行原子递增。
    # 只更新原先未标记的章节，避免无意义的重复增版。
    """项目上下文变化后，让已复核章节重新进入待复核状态。"""

    db.execute(
        update(Chapter)
        .where(
            Chapter.org_id == org_id,
            Chapter.project_id == project_id,
            Chapter.needs_review.is_(False),
        )
        .values(
            needs_review=True,
            lock_version=Chapter.lock_version + 1,
            updated_at=func.now(),
        )
    )
```

`populate_existing=True` 很重要：同一 Session 里前面查询过 Project，SQLAlchemy 会缓存对象。UPDATE RETURNING 后需要用数据库新值覆盖缓存，返回给前端的才是新版本号；失败诊断重新查也要刷新旧缓存。

普通用户修改项目必须带 expected_lock_version。批量标记复核属于服务端状态失效，在同一项目修改事务里执行，不要求客户端提交五个章节的版本；它使用数据库原子递增章节锁版本，避免章节用户拿旧版本继续保存。以后章节编辑、批准和项目更新应统一项目→章节的锁顺序。

**本节检查：** 能解释 exclude_unset 的用途；能从 UPDATE 中指出 org_id、id、lock_version 和 active 状态四个条件。

仓储中的 `**changes` 表示把字典拆成具名参数。例如 `{"description": "新描述"}` 传给 values 后，作用等同于 `.values(description="新描述")`。PATCH 的字段可变，所以这里才使用字典；创建接口仍逐项传递 name、construction_type 等固定字段。

## 6. 第五步：公共幂等执行器

先写幂等能力，再接项目服务，避免后面为了幂等把服务改成两套实现。

### 6.1 事务是关键

本教程采用适合短事务的实现：

```text
开启 app_runtime 租户事务
  → 查询持久化幂等记录
  → 已完成：重放；不同摘要：冲突；processing：稍后重试
  → 新请求：取得数据库事务级 advisory lock
  → 再查询一次（处理两个请求同时查不到记录的竞争）
  → 写 processing 记录
  → 执行业务：创建项目和五章 / 归档
  → 写 completed 与完整 JSON 响应
  → 一次提交
```

为什么同时用数据库锁和记录表？记录表保存重启后还能重放的结果；事务级 advisory lock 让正在执行、尚未提交的同键请求被第二个请求立即识别。仅查表不够：PostgreSQL 不会让另一个事务看到尚未提交的 processing 行。

这是 PostgreSQL 的锁，不是 Python 字典或单进程线程锁。所有服务进程都访问同一数据库，所以不同 Worker 之间也能协调。

异常或进程退出时事务回滚，项目、章节和幂等记录一起撤销，锁释放；若事务已提交但网络断了，重试就从 completed 记录返回原结果。不能在业务中途调用 commit，不能改用 OpsSessionLocal，不能在 action 里开启另一笔业务事务。

该实现不单独提前提交 processing 行，因此正常执行不会遗留“已提交的 processing，但资源状态不明确”。若未来导入或分阶段实现留下已持久化 processing，执行器会保守返回处理中，哪怕租约已过期。必须先核对资源和原事务，不盲目重新执行。A8 异步接口只把“建立 run + outbox + 返回 202”放进这个短事务，真正的后台执行不占着幂等锁。

```python
import hashlib
import uuid
from collections.abc import Callable
from dataclasses import dataclass
from datetime import UTC, datetime, timedelta
from typing import Any

from sqlalchemy import select, text
from sqlalchemy.orm import Session

from backend.app.core.errors import ApiError
from backend.app.core.pagination import canonical_json
from backend.app.core.principal import Principal
from backend.app.models.idempotency import IdempotencyKey


@dataclass(frozen=True)
class WriteResult:
    """一次写操作的状态码、JSON 响应和资源位置。"""

    status_code: int
    body: dict[str, Any]
    resource_type: str | None = None
    resource_id: uuid.UUID | None = None
    replayed: bool = False


def digest(value: str) -> str:
    """计算 SHA-256 摘要，不持久化原始幂等键。"""

    return hashlib.sha256(value.encode("utf-8")).hexdigest()


def validate_idempotency_key(key: str | None, *, required: bool) -> str | None:
    """区分可选和必需的幂等键，并检查长度和字符范围。"""

    if key is None and not required:
        return None
    # 使用可打印且不含空格的 ASCII；具体允许字符范围回写到 API 1.5。
    if (
        key is None
        or not 8 <= len(key) <= 128
        or not key.isascii()
        or not key.isprintable()
        or " " in key
    ):
        raise ApiError(
            422,
            "VALIDATION_ERROR",
            "Idempotency-Key 必须是 8 到 128 位可打印 ASCII 字符",
            details={"fields": [{"field": "Idempotency-Key", "reason": "长度或字符不合法"}]},
        )
    return key


def in_progress() -> ApiError:
    """相同请求尚未完成时，提示客户端稍后重试。"""

    return ApiError(
        409,
        "IDEMPOTENCY_IN_PROGRESS",
        "相同请求正在处理，请稍后重试",
        retryable=True,
        headers={"Retry-After": "1"},
    )


def cached_result(
    record: IdempotencyKey | None,
    *,
    request_hash: str,
    now: datetime,
) -> WriteResult | None:
    """检查已有记录，决定重放、冲突、处理中或允许执行新请求。"""

    if record is None:
        return None
    # processing 即使过期也不能盲目再次执行业务。
    if record.status == "processing":
        if record.request_hash != request_hash:
            raise ApiError(
                409,
                "IDEMPOTENCY_CONFLICT",
                "同一幂等键对应了不同请求",
            )
        raise in_progress()
    if record.expires_at <= now:
        return None
    if record.request_hash != request_hash:
        raise ApiError(
            409,
            "IDEMPOTENCY_CONFLICT",
            "同一幂等键对应了不同请求",
        )
    if record.response_status is None or record.response_json is None:
        raise RuntimeError("completed idempotency record has no response")
    return WriteResult(
        status_code=record.response_status,
        body=record.response_json,
        resource_type=record.resource_type,
        resource_id=record.resource_id,
        replayed=True,
    )


def execute_idempotent(
    db: Session,
    actor: Principal,
    *,
    key: str | None,
    method: str,
    canonical_path: str,
    payload: dict[str, Any],
    action: Callable[[], WriteResult],
) -> WriteResult:
    """使用当前租户事务协调业务副作用与持久化响应。"""

    if key is None:
        return action()

    key_hash = digest(key)
    request_hash = digest(canonical_json(payload))
    method = method.upper()
    statement = (
        select(IdempotencyKey)
        .where(
            IdempotencyKey.org_id == actor.org_id,
            IdempotencyKey.user_id == actor.user_id,
            IdempotencyKey.http_method == method,
            IdempotencyKey.canonical_path == canonical_path,
            IdempotencyKey.key_hash == key_hash,
        )
        .execution_options(populate_existing=True)
    )

    record = db.execute(statement).scalar_one_or_none()
    hit = cached_result(
        record,
        request_hash=request_hash,
        now=datetime.now(UTC),
    )
    if hit is not None:
        return hit

    scope = canonical_json(
        [
            str(actor.org_id),
            str(actor.user_id),
            method,
            canonical_path,
            key_hash,
        ]
    )
    # PostgreSQL 接收有符号 bigint；哈希碰撞最多导致保守的“处理中”，不会重放别人的数据。
    lock_id = int.from_bytes(
        hashlib.sha256(scope.encode()).digest()[:8],
        "big",
        signed=True,
    )
    acquired = db.execute(
        text("SELECT pg_try_advisory_xact_lock(:lock_id)"), {"lock_id": lock_id}
    ).scalar_one()
    if not acquired:
        raise in_progress()

    # 在拿锁后再读，避免另一事务恰好在第一次 SELECT 后完成。
    record = db.execute(statement).scalar_one_or_none()
    now = datetime.now(UTC)
    hit = cached_result(
        record,
        request_hash=request_hash,
        now=now,
    )
    if hit is not None:
        return hit

    if record is None:
        record = IdempotencyKey(
            id=uuid.uuid4(),
            org_id=actor.org_id,
            user_id=actor.user_id,
            http_method=method,
            canonical_path=canonical_path,
            key_hash=key_hash,
            request_hash=request_hash,
            status="processing",
        )
        db.add(record)
    # 已完成且过期的同作用域记录通过 UPDATE 复用，不需要 DELETE 授权。
    record.request_hash = request_hash
    record.status = "processing"
    record.processing_owner = uuid.uuid4()
    record.processing_expires_at = now + timedelta(minutes=1)
    record.response_status = None
    record.response_json = None
    record.resource_type = None
    record.resource_id = None
    record.expires_at = now + timedelta(hours=24)
    record.updated_at = now
    db.flush()

    result = action()
    record.status = "completed"
    record.response_status = result.status_code
    record.response_json = result.body
    record.resource_type = result.resource_type
    record.resource_id = result.resource_id
    record.processing_owner = None
    record.processing_expires_at = None
    record.updated_at = datetime.now(UTC)
    db.flush()
    return result
```

几个需要亲自理解的地方：

1. 作用域包含具体资源 UUID。`/projects/甲/archive` 与 `/projects/乙/archive` 不共享记录，不能用 `/projects/{project_id}/archive` 作为持久化路径。
2. 路由手工构造 canonical_path，UUID 转成标准小写带连字符形式，避免同一个 UUID 的不同写法造成不同作用域。
3. 创建请求先由 Pydantic 校验，路由再逐项传参；服务用这些参数建立 request_data 字典作为摘要输入。显式默认值与省略默认值视为同一创建请求。PATCH 若以后支持幂等，应使用 exclude_unset，保留“省略与清空”的差异。
4. 完成响应必须是已经能写 JSONB 的数据，UUID 和 datetime 要先变成字符串。不能保存 Response 对象、Cookie 或令牌。
5. 不缓存业务失败。action 抛出异常就整笔回滚，用户修正或刷新后可以再次尝试；前提是重试仍满足版本和权限。
6. 记录过期后允许把同键当新请求，不代表旧项目消失。创建项目在 24 小时之后重试可能新建项目，客户端不能无限期盲重试。
7. 一个真正正在执行的事务，其 processing 行未提交，因此竞争请求可能只能得到 IN_PROGRESS，无法立即知道请求体是否不同；它稍后重试时会得到精确的重放或 CONFLICT。已可见的记录会优先校验摘要。这一并发时序需要在 API 1.5 回写说明。

这里依靠默认 PostgreSQL READ COMMITTED 隔离级别，让拿锁后的第二次查询能看到对方刚提交的记录。当前 create_engine 没有配置其他隔离级别，与此一致。未来若改成 REPEATABLE READ，需要重新设计这段读取行为。

**本节检查：** 能描述“第一次查不到记录”的两个并发请求如何协调；能说明为什么只写唯一约束仍不足以返回及时的处理中响应。

```python
def create_project(
    actor: Principal,
    session_factory: sessionmaker[Session],
    *,
    name: str,
    construction_type: str,
    description: str = "",
    data_classification: str = "synthetic",
    request_id: str,
    idempotency_key: str | None,
) -> WriteResult:
    """在同一事务创建项目、默认五章和可选的幂等结果。"""
    authorize(actor, Permission.EDIT_CONTENT)

    request_data = {
        "name": name,
        "construction_type": construction_type,
        "description": description,
        "data_classification": data_classification,
    }

    with tenant_transaction(actor, session_factory) as db:

        def create_project_action() -> WriteResult:

            project = Project(
                id=uuid.uuid4(),
                org_id=actor.org_id,
                created_by=actor.user_id,
                name=name,
                construction_type=construction_type,
                description=description,
                data_classification=data_classification,
                status="active",

def update_project(
    actor: Principal,
    session_factory: sessionmaker[Session],
    *,
    project_id: uuid.UUID,
    expected_lock_version: int,
    changes: dict[str, Any],
) -> dict[str, object]:
    """只修改已提交字段，最终由带版本号的 UPDATE 保证并发安全。"""
    with tenant_transaction(actor, session_factory) as db:
        project = require_project(
            db,
            actor,
            project_id=project_id,
        )

        authorize(actor, Permission.EDIT_CONTENT)
        require_active(project)

        # 复制路由提供的字段，不把 baseline_dirty 写回调用方的原字典。
        update_values = dict(changes)
        affects_baseline = False

        if "name" in update_values and update_values["name"] != project.name:
            affects_baseline = True

        if (
            "construction_type" in update_values
            and update_values["construction_type"] != project.construction_type
        ):
            affects_baseline = True

        if affects_baseline:
            update_values["baseline_dirty"] = True

        updated = update_project_if_version_matches(
            db,
            org_id=actor.org_id,
            project_id=project_id,
            expected_lock_version=expected_lock_version,
            changes=update_values,
        )

        if updated is None:
            raise project_update_error(
                db,
                actor,
                project_id=project_id,
            )

        if affects_baseline:
            mark_chapters_for_review(
                db,
                org_id=actor.org_id,
                project_id=project_id,
            )

        return project_summary(updated)

def archive_project(
    actor: Principal,
    session_factory: sessionmaker[Session],
    *,
    project_id: uuid.UUID,
    expected_lock_version: int,
    request_id: str,
    idempotency_key: str,
) -> WriteResult:
    """管理员归档项目，要求版本匹配并保存幂等响应。"""
    with tenant_transaction(actor, session_factory) as db:
        # 重放前也检查归属和权限，不能借缓存绕过当前身份校验。
        require_project(
            db,
            actor,
            project_id=project_id,
        )
        authorize(actor, Permission.ARCHIVE_PROJECT)

        def archive_project_action() -> WriteResult:
            """重放无需再次归档，新请求才进入这里检查状态并修改。"""
            project = db.execute(
                select(Project)
                .where(
                    Project.org_id == actor.org_id,
                    Project.id == project_id,
                )
                .with_for_update()
                .execution_options(populate_existing=True)
            ).scalar_one_or_none()

            if project is None:
                raise resource_not_found()

            require_active(project)
            ensure_no_active_runs(
                db,
                actor,
                project_id=project_id,
            )

            updated = update_project_if_version_matches(
                db,
                org_id=actor.org_id,
                project_id=project_id,
                expected_lock_version=expected_lock_version,
                changes={"status": "archived"},
            )

            if updated is None:
                raise project_update_error(
                    db,
                    actor,
                    project_id=project_id,
                )

            return WriteResult(
                status_code=200,
                body={"data": project_summary(updated), "request_id": request_id},
                resource_type="project",
                resource_id=project_id,
            )

        result = execute_idempotent(
            db,
            actor,
            key=idempotency_key,
            method="POST",
            canonical_path=f"/api/v1/projects/{project_id}/archive",
            payload={"expected_lock_version": expected_lock_version},
            action=archive_project_action,
        )

        return result
```

`project_update_error()` 和你原来的 `resource_not_found()` 一样，负责构造并返回 ApiError；调用方显式写 `raise project_update_error(...)`。这样能直接看出异常在哪里抛出，类型检查器也能确认后面的 updated 已经不是 None。路由请求模型通过 extra="forbid" 阻止传入任意字段，changes 只来自已校验请求中实际提交的可修改字段。

这份服务继续采用你原来“明确传入 project_id、expected_lock_version”的方式。创建服务逐项接收固定字段；修改服务接收 changes 字典，是因为 PATCH 每次提交的字段数量不固定。请求模型校验留在路由入口，服务处理业务规则和事务。

`create_project_action()` 和 `archive_project_action()` 是写在服务内部的具名函数。定义它们时还不会执行其中的 SQL；`execute_idempotent()` 确认需要执行新请求之后，才通过 action() 调用它们。它们使用外层的 db，因此业务记录和幂等结果始终在同一事务内。

这里项目行锁与版本条件一起使用：行锁给 A8 的“检查运行 + 归档”提供同一事务内的协调点；最终 UPDATE 依旧带 expected_lock_version，不能因为有 FOR UPDATE 就省略乐观锁。

### 7.3 名称变化为什么影响基准

项目名称和工程类型会影响生成与审核上下文。修改它们后必须在同一事务设置 `baseline_dirty=True`，并将章节的 needs_review 改为 true。描述和数据分类按当前 API 第 5 节没有被列为触发条件，所以教程没有自行扩展触发范围；若产品将来扩大规则，需要同步修改服务、测试和合同。

`baseline_dirty` 不会在修改描述时被清成 false。只有真正发布基准的流程才有资格清它。

### 7.4 归档和版本冲突的顺序

当前规则为：跨组织或不存在 → 404；本组织没有权限 → 403；已经归档 → PROJECT_ARCHIVED；active 项目版本不匹配 → VERSION_CONFLICT。同键同体归档重放会在检查“已归档”之前返回首次结果；新键再次归档仍走只读规则。

读取 Project 是为了权限、状态和变更语义，**并发正确性由带版本的 UPDATE 保证**。两个请求都读到版本 1 也没有关系，最终只有一个能执行 `WHERE lock_version=1`，另一个影响零行。

**本节检查：** 创建项目和五章只有一次事务提交；归档和 PATCH 都使用同一个带版本条件的仓储函数；名字变化的项目和章节更新在同一事务。

响应通过 response_model 校验并生成 OpenAPI，首次写响应和重放都经过同一套序列化。业务服务在退出 tenant_transaction 时已经提交，路由不再 commit。

**本节检查：** `/docs` 能看到五个接口；创建显示 201；归档有 Idempotency-Key 请求头；PATCH 模型没有 org_id；GET 不需要 CSRF。

```python
def test_inflight_transaction_returns_in_progress(
    a6_data: A6Data,
    parallel_factory: sessionmaker[Session],
) -> None:
    """第一笔事务尚未提交时，竞争请求也应立即识别处理中。"""

    entered = threading.Event()
    release = threading.Event()

    def first_request() -> WriteResult:
        with tenant_transaction(a6_data.admin, parallel_factory) as db:

            def action() -> WriteResult:
                entered.set()
                if not release.wait(timeout=10):
                    raise RuntimeError("test release timeout")
                return WriteResult(201, {"data": {"value": 1}, "request_id": "first"})

            return execute_idempotent(
                db,
                a6_data.admin,
                key="inflight-test-001",
                method="POST",
                canonical_path="/test/inflight",
                payload={"value": 1},
                action=action,
            )

    with ThreadPoolExecutor(max_workers=1) as pool:
        future = pool.submit(first_request)
        try:
            assert entered.wait(timeout=10)
            with (
                pytest.raises(ApiError) as exc,
                tenant_transaction(a6_data.admin, parallel_factory) as db,
            ):

                def unexpected_action() -> WriteResult:
                    """竞争请求不应该再次执行业务。"""
                    return WriteResult(201, {"wrong": True})

                execute_idempotent(
                    db,
                    a6_data.admin,
                    key="inflight-test-001",
                    method="POST",
                    canonical_path="/test/inflight",
                    payload={"value": 1},
                    action=unexpected_action,
                )
            assert exc.value.code == "IDEMPOTENCY_IN_PROGRESS"
        finally:
            release.set()
        assert future.result(timeout=15).status_code == 201
```

### 11.1 API 文档回写

建议将以下补充加入 `docs/dev/API文档.md` 的对应小节，字段和错误码以最终实现为准。

**第 1.2 节补充请求跟踪：**

> 每次 HTTP 请求生成独立 request_id，写入服务端日志和 X-Request-ID 响应头。普通 JSON 响应的 request_id 与响应头一致。幂等重放保留原 JSON 响应及其中的原 request_id，X-Request-ID 表示本次 HTTP 请求；同时返回 Idempotency-Replayed: true。

**第 1.3 节明确列表默认条件：**

> 项目列表未提供 status 时返回本组织全部状态，客户端如需仅显示有效项目应明确传 status=active。q 按名称进行不区分大小写的字面子串匹配，% 和 _ 不作为通配符。游标绑定当前组织、用户、q、status 与排序规则；limit 可在翻页时调整。

**第 1.5 节细化幂等键和并发时序：**

> Idempotency-Key 使用 8—128 位、不含空格的可打印 ASCII 字符（0x21—0x7E）。请求摘要基于通过校验的字段和规范 JSON，JSON 键顺序不影响摘要。短事务正在执行且记录尚未提交时，同键竞争优先返回 409 IDEMPOTENCY_IN_PROGRESS、retryable=true、Retry-After: 1；重试时按可见的已提交记录判定重放或 IDEMPOTENCY_CONFLICT。已持久化 processing 记录租约过期不能自动重做，必须先核查已提交资源。

**第 5 节补充实现的细节：**

> POST /projects 可选 Idempotency-Key；有键时遵循通用幂等规则，无键时每次为独立创建。创建默认根目录依次为施工方案/construction、进度安排/schedule、质量保证/quality、安全文明施工/safety、资源配置/resources，position=0—4。name、construction_type 去掉两端空白后验证长度。PATCH 至少包含一个可修改字段；已提供字段不得为 null，description="" 可清空。归档成功返回 200 和 Project；已归档对象使用新幂等键再次归档返回 PROJECT_ARCHIVED。

**第 14 节补充错误码：**

| HTTP | code | 场景 |
|---|---|---|
| 405 | METHOD_NOT_ALLOWED | 路径存在但请求方法不支持 |
| 原 HTTP 状态 | HTTP_ERROR | 未单独定义业务码的框架 HTTP 错误兜底 |
| 500 | INTERNAL_ERROR | 未预期服务端异常，隐藏内部详情 |

RUNS_ACTIVE 是原合同已有的错误码，A6 只标记待实现，不要删除它。

### 11.2 数据库文档回写

在 `docs/dev/数据库文档.md` 第 8.1 节补阶段说明：

> A6 已建立 app.chapters 目录基础：组织、项目、父节点、标题、类型、顺序、needs_review、创建者、时间、lock_version 与同项目复合外键、同级唯一顺序约束。selected_version_id 及其复合外键随 C4 正文版本表加入；chapter_requirements 随对应要求映射功能加入。目录编辑 API 的循环检查在该 API 实现时补齐。

第 12.2 节补实现说明：

> A6 的短事务幂等通过 PostgreSQL 事务级 advisory lock 协调尚未提交的同键请求，completed 结果持久化在 ops.idempotency_keys。业务副作用与 completed 响应使用同一 app_runtime Session 和同一事务，失败全部回滚。正常处理不会提前提交 processing 行。app_runtime 仅有 SELECT/INSERT/UPDATE；已完成过期记录原位复用，历史记录清理由维护角色完成。ops_runtime 无权读取本表。

第 16 节记下实际 revision ID 与前置修订，不重写逻辑分组表，也不把教程给出的日期当作迁移执行证据。

### 11.3 A8 需要回填什么

找到 `ensure_no_active_runs()` 的 TODO，完成以下事情：

1. 引入真实 Run 模型，在**同一个 Session** 查询 `org_id + project_id` 下的非终态运行。
2. 非终态包括 `queued`、`running`、`waiting_input`；终态按当时的 Run 状态合同核对。不要只阻止 running 而漏掉等待人工输入的任务。
3. 存在任一非终态运行时抛 `ApiError(409, "RUNS_ACTIVE", "项目仍有未结束的后台任务")`。可以给出计数或运行 ID，但不能泄露其他组织数据。
4. 创建、恢复以及其他从终态产生新运行的服务也必须遵守同一个项目行锁，并在锁内重新检查项目 active。否则“先检查没有任务，再归档”仍然可能与新建运行竞争。
5. 保持项目→运行→章节等一致锁顺序，避免不同服务反向锁导致死锁。
6. 把 skip 测试改为参数化真实测试，覆盖各非终态、全部终态允许归档，以及“归档与创建运行同时发生”的竞争。

## 12. 常见错误的排查顺序

| 现象 | 常见原因 | 检查位置 |
|---|---|---|
| 写接口返回 403 CSRF_INVALID | Cookie/Token 不配套，或 Origin 不符 | 登录、require_csrf、Origin 配置 |
| 业务 SELECT 看不到任何行 | 没进入 tenant_transaction | 服务事务入口；别改成管理员连接 |
| 插章节时提示外键失败 | org_id/created_by 不一致，或没 flush 父项目 | 创建服务的两次 flush |
| 根目录能有两个 position=0 | 没有 COALESCE 表达式唯一索引 | 迁移与 Chapter 索引 |
| PATCH 成功但返回旧版本 | ORM identity map 没刷新 | RETURNING + populate_existing |
| 两个版本 1 都成功 | UPDATE 条件中没版本号 | update_project_if_version_matches |
| 幂等重试又建了一个项目 | 换了键、超 24 小时、或作用域构造不同 | 请求头、canonical_path、expires_at |
| 幂等第二次长时间等待 | 只靠唯一索引，没有即时竞争检测 | pg_try_advisory_xact_lock |
| 归档重试得到 PROJECT_ARCHIVED | 在重放判断前检查了 active | archive 的 action 与 execute_idempotent 顺序 |
| 翻页遗漏同时间的数据 | 锚点缺少 id 或用了多取的第 21 条 | fetch 条件与 paginate |
| 改过滤条件还能用旧游标 | 没有验证过滤摘要 | filters 与 decode_cursor |
| Alembic 提示表已存在 | 新迁移再次创建 projects | 迁移链与历史 A5 迁移 |
| mypy 报 updated 可能为 None | 零行分支没有显式 raise，仍继续往下执行 | if updated is None 分支与 project_update_error |
| 并发测试像串行 | 共用 Session，或连接池只有一条连接 | parallel_factory |

处理错误时保留 HTTP 状态、error.code、request_id 和对应日志；不要把 Cookie、密码、数据库 URL 和完整请求正文发到公共渠道。
