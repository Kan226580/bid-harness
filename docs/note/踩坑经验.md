# 踩坑经验

> 记录开发中遇到的困难以及最终的解决方案

## 数据迁移

```bash
uv add sqlalchemy "psycopg[binary]" alembic
uv run alembic init migrations

uv run alembic revision --autogenerate -m "0001 identity"
uv run alembic upgrade head
```

- 问题1

> 同schema下的表因为缺少schema导致无法迁移

- 解决方案

> 1. `env.py` 中 context.configure 添加 include_schemas=True
> 2. `/version` 中的迁移文件手动添加 op.execute ("CREATE SCHEMA IF NOT EXISTS auth") 和 op.execute ("DROP SCHEMA IF NOT
     EXISTS auth CASCADE")

- 问题2

> `auth` 中的 settings_json 中的 server_default 设置的json格式有误

- 解决方案

> 在json的键冒号后空一格再跟值

- 修改对比

> 1. settings_json: Mapped[dict[str, Any]] = mapped_column (JSONB, nullable=False, server_default=text (
     """'{"run_max_calls":null,"run_max_tokens":null,"run_max_cost_cny":null}'::jsonb"""
     ),

## Docker

```bash
docker compose --env-file ./.env --env-file ./.env.admin -f deploy/compose.yaml up -d
docker compose --env-file ./.env --env-file ./.env.admin -f deploy/compose.yaml ps
docker compose --env-file ./.env --env-file ./.env.admin -f deploy/compose.yaml logs postgres
```

- 问题
> 数据库 用户/密码 组合明文写入会导致数据库暴露

- 解决方案
> 1. 在 compose.yaml 中为 postgres 和 redis 添加 environment 字段
> 2. environment 字段从 .env 文件中读取相关配置
> 3. 命令行中加入 --env-file ./.env 指向需要读取的环境配置

## ci

- ruff

```bash
uv run ruff check --fix .
uv run ruff format .
uv run ruff format --check .
```

- mypy

```bash
uv run mypy
``` 

- 问题1

> 1. mypy 从设计上不支持「装饰器套在 @property 上面」
> 2. DbSettings/RedisSettings 有必填字段，该类零参数不可调用，不能当 default_factory

- 解决方法

> 1. 在 @computed_field 那一行加 # type: ignore[prop-decorator]
> 2. 去掉默认值default_factory，声明为必填：db: DbSettings、redis: RedisSettings

- 问题2

> 1. 本地 `.env` 不允许上传到远程仓库
> 2. 本地有数据库配置， mypy 检查正常
> 3. 远程仓库没有相应的数据库配置，无法通过 mypy 检查

- 解决方法

> 1. 将后端环境 `env` 写进 ci.yml
